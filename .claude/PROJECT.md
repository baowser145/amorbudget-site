# PROJECT.md — amorbudget-site

Marketing/landing site for Amor Budget (the native iOS budgeting app at `/Users/vubl/projects/amor-budget`). Astro static site, deployed to Vercel, live at https://amorbudget.com. Reuses the app's exact brand tokens (Olive & Blush palette, self-hosted Nunito) rather than a separate visual identity — a deliberate choice so the site and app read as the same product.

Repo: https://github.com/baowser145/amorbudget-site (public)

## Standing Notes
- **Brand tokens live in `/Users/vubl/projects/amor-budget/src/theme/variables.css`** — this site's `src/styles/global.css` copies them verbatim (`--ab-accent`, `--ab-gold`, etc. plus a couple of site-only additions like `--muted-copy` for marketing-copy contrast that the app's own `--ab-muted` doesn't meet at body-text sizes). If the app's palette changes, this site's copy needs to be updated too — there's no shared token source between the two repos.
- **Real app screenshots, not mockups.** Hero and Screenshots sections use actual simulator screenshots of the app (Login, Home tab) rather than illustrations — see `src/assets/screenshots/`. These will look stale once the app ships the new icon; retake them at that point.
- **Deploy**: push to `main` → Vercel auto-deploys. DNS is on Cloudflare (both `amorbudget.com` and `www` CNAME records, DNS-only/grey-cloud, not proxied — Vercel needs to see the connection directly for its own SSL).
- **The icon's canonical SVG path data is recorded in `.claude/HANDOFF.md`** under "The icon's source SVG" — treat that as the source of truth, not any scratchpad file (session scratchpads don't persist).
- **Chrome automation's `resize_window` tool has been unreliable on a tab already in use this session** — it silently no-ops (window stays at its previous size) when called against a tab that's already navigated/interacted with. Opening a brand-new tab first, then resizing that fresh tab, has worked consistently for mobile-viewport testing.
