- **Real app screenshots, not mockups.** Only `src/assets/screenshots/home.png` (1206×2622) and `login.png` exist, and the app repo has none — capturing more means running amor-budget with real data (Supabase login). **If `home.png` is ever recaptured, re-measure the three spotlight rects in `Screenshots.astro`** — they are percentages measured off the current source and a new screenshot silently invalidates them.
- **Canonical host is `www.amorbudget.com`.** The apex 308-redirects to www. `site` in `astro.config.mjs` must stay on the www host, or og:image/og:url/canonical all resolve through a redirect.
- **Deploy**: push to `main` → Vercel auto-deploys (~30-60s). DNS is on Cloudflare (both apex and `www`, DNS-only/grey-cloud, not proxied — Vercel needs to see the connection directly for its own SSL).
- **Regenerating `public/og.png`**: the generator script lived in a session scratchpad and does **not** persist. The method: `@fontsource/nunito` ships only `.woff2`/`.woff`, neither of which fontconfig can read, so convert the weights to TTF with `fontTools` (`TTFont(src); f.flavor = None; f.save(out)`), write a throwaway `fonts.conf` pointing `<dir>` at them, then run a sharp script with `FONTCONFIG_FILE=` set so SVG text renders in real Nunito instead of a fallback. Note SVG collapses whitespace between `<tspan>`s — use `dx` for the gap, not a space or `&#160;`. Nothing was installed to the system.
- **Astro dev server can serve stale component CSS.** Hit this hard: markup hot-reloaded but the `<style>` block kept serving the previous version, so new selectors silently never applied and the section looked broken. Diagnose by curling `/src/components/X.astro?astro&type=style&index=0&lang.css` and grepping for a new selector. Fix: `astro dev stop`, `rm -rf node_modules/.vite`, restart.
- **Chrome automation's `resize_window` does not work in this environment** — it reports success and no-ops, even against a freshly created tab (an earlier note claimed a fresh tab was a reliable workaround; that is no longer true). For responsive checks, inject iframes at fixed pixel widths into a page and screenshot those — media queries evaluate against iframe width and it works reliably. Also note the screenshot tool often captures a frame mid-transition; take a second screenshot to see the settled state.
