## Shopify Horizon theme — hard-won facts
Recorded here rather than in HANDOFF.md so they survive handoff overwrites. All learned by reading the theme source; `search_docs_chunks` returns nothing useful for Horizon section schemas.

- **`_media-without-appearance` does not inherit the section's product.** It is a generic media block with its own `image` picker, and Horizon's own `featured-product` preset ships it empty — which renders a teal placeholder illustration. It expects a merchant-chosen editorial shot. This is the single most confusing thing in the theme.
- **`hero.liquid` renders a stock `hero-apparel-1` placeholder whenever `media_count == 0`.** A text-only hero is impossible; it must have an image. Setting ids are `image_1`/`image_2`, plus `image_1_mobile` gated behind `custom_mobile_media: true`. Values take the form `shopify://shop_images/<filename>`.
- **A "large" hero crops harder on wider monitors** — roughly 2.6:1 at 1459px wide, ~3.4:1 at 1920px. Compose hero subjects inside the central ~70% of the canvas or they lose their edges on big screens.
- **`featured-product` blocks are `static: true` and referenced by exact id in Liquid** (`media`, `featured-product`, and nested `featured-product-title`, `-price`, `-gallery`, `-swatches`). Hand-authored JSON must reproduce those ids exactly.
- **Section files are big** — `hero.liquid` 44KB, `header.liquid` 54KB, `section.liquid` 54KB. Read `featured-product.liquid` (5.8KB) or `marquee.liquid` (4.4KB) first as cheap pattern examples.
- **Blocked by MCP safety policy, by design**: `themePublish`, storefront password protection, shop address, domain creation. `themeFilesUpsert` works but only on unpublished themes, and Claude Code's own auto-mode classifier may block it until the user approves.
- **`menuUpdate` is store-level, not theme-level** — changing the nav affects the live storefront immediately even when every theme edit is confined to a draft.
- **Once the theme is live you cannot write to it at all**; the MCP rejects `themeFilesUpsert` against MAIN. Run `themeDuplicate` first, edit the copy, and hand the publish back to the user. Every subsequent round of changes needs its own duplicate-then-publish cycle.
- **Minify JSON before upserting it.** A pretty-printed `templates/index.json` (~7KB) truncates in transit and comes back as an unparseable-JSON tool error. The same content on one line goes through fine, and the theme editor reformats it anyway.
- **The generic `section` type shares the hero's layout vocabulary** (`content_direction`, `horizontal_alignment_flex_direction_column`, `section_width`, `section_height`, `background_color`, `padding-block-*`) and accepts ordinary `text`/`button` blocks. `section_width: "full-width"` gives an edge-to-edge colour band. For a centred paragraph inside one, `max_width: "narrow"` is far too tight (~310px) and `"wide"` runs the full viewport; `"normal"` (~440px) is the readable one.
- **`logo` and `favicon` are plain `config/settings_data.json` keys** taking `shopify://shop_images/<filename>`. Horizon builds the 1x/2x/3x srcset off `logo_height` (36) and `logo_height_mobile` (28) on its own.
- **Uploading an image**: `stagedUploadsCreate` → `curl -F` POST to the signed GCS target with the file field last (expect HTTP 201) → `fileCreate` with the returned `resourceUrl` → poll `files(sortKey: CREATED_AT, reverse: true)` until `fileStatus: READY` to learn the final filename.
- **Product photos are flat mockups on pure `#ffffff`** against a cream `#f7f4ec` page, so they show as white boxes. To composite the garment onto a brand field: flood-fill inward from the border (`tolerance` ~22) so only edge-connected white is dropped — a luminance key makes the cream shirt itself translucent — then `MinFilter(9)` to erode the mockup's baked-in white halo, feather ~1.6px, and add ~2% noise to the destination field or large flat areas band under JPEG.

The method: `@fontsource/nunito` ships only `.woff2`/`.woff`, neither of which fontconfig can read, so convert the weights to TTF with `fontTools` (`TTFont(src); f.flavor = None; f.save(out)`), write a throwaway `fonts.conf` pointing `<dir>` at them, then run a sharp script with `FONTCONFIG_FILE=` set so SVG text renders in real Nunito instead of a fallback. Note SVG collapses whitespace between `<tspan>`s — use `dx` for the gap, not a space or `&#160;`. Nothing was installed to the system.
- **Astro dev server can serve stale component CSS.** Hit this hard: markup hot-reloaded but the `<style>` block kept serving the previous version, so new selectors silently never applied and the section looked broken. Diagnose by curling `/src/components/X.astro?astro&type=style&index=0&lang.css` and grepping for a new selector. Fix: `astro dev stop`, `rm -rf node_modules/.vite`, restart.
- **Chrome automation's `resize_window` does not work in this environment** — it reports success and no-ops, even against a freshly created tab (an earlier note claimed a fresh tab was a reliable workaround; that is no longer true). For responsive checks, inject iframes at fixed pixel widths into a page and screenshot those — media queries evaluate against iframe width and it works reliably. Also note the screenshot tool often captures a frame mid-transition; take a second screenshot to see the settled state.
